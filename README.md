# Telegram Political Newsroom

დამოუკიდებელი ქართულენოვანი პოლიტიკური საინფორმაციო სისტემის პირველი საინჟინრო ვერსია.
ყველა პოსტი საჭიროებს მფლობელის **Publish / Edit / Cancel** მოქმედებას Telegram-ში.
ტექნოლოგიური არხის პროექტი, ბოტი, მონაცემები და გასაღებები არ გამოიყენება.

**სტატუსი:** კოდი და ოფლაინ ტესტები; რეალური Telegram/OpenAI ინტეგრაციის პილოტი აუცილებელია.
სარედაქციო განრიგი, წყაროების სია და სიტყვების ლიმიტები მფლობელმა უნდა განსაზღვროს.
პირველადი კონფიგურაციით worker, scheduler და გამოქვეყნება გამორთულია.

## შესაძლებლობები

- OpenAI Responses + Web Search: კანდიდატების აღმოჩენა, მოვლენების დაჯგუფება, მნიშვნელობის შეფასება.
- წყაროს URL მიიღება მხოლოდ ძებნის რეალურად დაბრუნებული ბმულებიდან და დომენების allowlist-იდან.
- წყაროს ტექსტის ჩამოტვირთვა: HTTPS, DNS/IP კონტროლი, redirect-ის ხელახალი შემოწმება, ზომის/დროის ლიმიტები.
- მტკიცებების სტატუსები: verified / attributed / unverified / disputed; წყაროები, მოკლე ციტატები და წინააღმდეგობები.
- Structured Outputs, ფაქტების მეორე შემოწმება და ფორმატის ვალიდაცია.
- PostgreSQL: დავალებების რიგი, მონახაზები, ვერსიები, დამტკიცებები, გამოქვეყნების შედეგი და აუდიტი.
- URL/სათაური/მოვლენის გასაღები და დამატებითი მოდელური შედარება დუბლიკატების წინააღმდეგ.
- რეალური Commons ფოტოები ავტორის/ლიცენზიის მონაცემებით; გენერირებული ფოტოები არ გამოიყენება.
- webhook secret, მფლობელის კონტროლი, განმეორებითი update-ის ბლოკირება და ვერსიაზე მიბმული ღილაკები.
- API მოთხოვნების, გამოშვებებისა და output-ის ლიმიტები; token/search გამოყენების აღრიცხვა.
- scheduler-ის heartbeat, 15-წუთიანი catch-up და მონაცემთა ბაზაში უნიკალური განრიგის გასაღები.

## Pipeline

Discover → Cluster → Score → Retrieve → Verify → Draft → Fact Check → Licensed Image → Approval → Publish → Archive.

კვლევის წყაროების allowlist ცარიელია განზრახ. დომენების არჩევა არ არის წყაროს მიერ გამოქვეყნებული ყველა
მტკიცების დადასტურება. პირველწყაროს განცხადება და დამოუკიდებელი დადასტურება სხვადასხვა რამეა.
ერთი და იმავე სააგენტოს/პრესრელიზის გადაბეჭდვა დამოუკიდებელ მტკიცებულებად არ უნდა ჩაითვალოს.
`SOURCE_ORIGIN_GROUPS` გამოიყენება ცნობილ საერთო მფლობელთა/წარმომავლობის დასაფიქსირებლად.

მოდელური შეფასება, ორიგინალის ამოცნობა და ციტატის დამთხვევა **არ წარმოადგენს ფაქტობრივი სისწორის
გარანტიას**. მოდელს შეიძლება შეეშალოს თარიღი, დამოუკიდებლობა ან ტექსტის მნიშვნელობა. მფლობელი ამოწმებს
წყაროებსა და გაურკვევლობებს დამტკიცებამდე. მიუწვდომელი/სუსტი წყაროებისას სისტემა პოსტს აჩერებს.

## Telegram

1. შექმენი **ახალი** BotFather ბოტი და ცალკე პოლიტიკური არხი.
2. ბოტი დაამატე არხის ადმინისტრატორად, პოსტების გამოქვეყნების უფლებით.
3. პირად ჩატში გაუგზავნე `/start`.
4. Railway Variables-ში შეიტანე დამოუკიდებელი bot token, owner ID, channel ID და API key.
5. მიუთითე `EXPECTED_BOT_USERNAME`; CLI webhook-ის რეგისტრაციამდე ამოწმებს ბოტის ვინაობას.
6. `PUBLIC_BASE_URL` მიუთითე ახალი სერვისის HTTPS მისამართად.
7. კონფიგურაციისა და გაშვების შემდეგ ცალკე შეასრულე `political-agent register-webhook`.

Webhook-ის რეგისტრაცია startup-ისას ავტომატურად არ ხდება. ეს იცავს სხვა ბოტის webhook-ის შემთხვევით შეცვლას.
`CHANNEL_ID=@Cifruli_Era` აკრძალულია. არსებული ბოტის token **არ დააკოპირო**.

ბოტის ბრძანებები:

| ბრძანება | მოქმედება |
|---|---|
| `/news მოთხოვნა` | მოამზადებს ახალ მონახაზს |
| `/pending` | მიმდინარე მონახაზების სია |
| `/show ID` | მონახაზის ხელახალი ჩვენება |
| `/status` | რიგი, მონახაზები, გამოყენების მრიცხველები |
| `/edit ID:VERSION` | შემდეგ ხაზებზე სათაური, ცარიელი ხაზი, ტექსტი |

Edit ქმნის ახალ ვერსიას და ხელახლა ამოწმებს ტექსტს იმავე მტკიცებულებებზე. ახალი ფაქტის დასამატებლად
საჭიროა ახალი კვლევა. ჩვეულებრივი ტექსტის ან ფოტოს გაგზავნა პოსტს ავტომატურად არ აქვეყნებს.

## გამოქვეყნების დაცვა

`pending → editing → pending (version+1)` ან `pending → publishing → published`.
Cancel → `cancelled`. ვადაგასული მონახაზის Publish იბლოკება.

არხში გაგზავნამდე ინახება დამტკიცება. განმეორებითი დაჭერა ვეღარ იწყებს მეორე გაგზავნას.
Timeout/კავშირის დაკარგვა/გაურკვეველი შედეგი → `unknown`; restart ავტომატურად არ აგზავნის თავიდან.
თუ Telegram-მა მიიღო პოსტი, მაგრამ DB-ში შედეგის შენახვა ჩავარდა, რჩება `publishing`, შემდეგ `unknown`.
ეს არის დუბლიკატის შემცირების მექანიზმი; ქსელის გამო აბსოლუტური exactly-once გარანტია არ გვაქვს.

ერთი გამოქვეყნება = ერთი Telegram შეტყობინება. მოკლე ტექსტი შეიძლება გამოქვეყნდეს ფოტოს caption-ად,
ხოლო გრძელი პოსტი ტექსტურად ქვეყნდება. ფოტო+ცალკე გრძელი ტექსტის ნაწილობრივი გამოქვეყნება არ გამოიყენება.
ფოტოს ავტორი/ლიცენზია და საარქივო/საილუსტრაციო აღნიშვნა თან ახლავს; შერჩეული ფაილის SHA-256 მოწმდება.

## ადმინისტრირება

ადმინისტრაციული API მოითხოვს `Authorization: Bearer <ADMIN_API_TOKEN>`-ს (მინიმუმ 32 სიმბოლო).
გასაღებები არასოდეს მიუთითო URL-ში. ინტერაქტიული Swagger გამორთულია.

| Endpoint | დანიშნულება |
|---|---|
| `GET /health` | პროცესისა და DB კავშირის healthcheck |
| `GET /ready` | კონფიგურაცია და worker heartbeat |
| `GET /admin/status` | რიგი, მდგომარეობები, გამოყენება, პარამეტრების ნაკლებობა |
| `POST /admin/generate` | `{ "query": "...", "post_format": "STANDARD" }` |
| `GET /admin/jobs/{id}` | დავალების შედეგი |
| `GET /admin/drafts` | ბოლო 100 მონახაზი |
| `GET /admin/drafts/{id}` | ტექსტი, წყაროები და მტკიცებულებები |
| `POST /admin/drafts/{id}/edit` | `{ "version": 1, "title": "...", "body": "..." }` |
| `POST /admin/drafts/{id}/notify` | მოლოდინში არსებული მონახაზის ხელახალი ჩვენება |
| `POST /admin/drafts/{id}/reconcile` | არხში ხელით ნაპოვნი `{ "message_id": 123 }` |

API-ს გამოქვეყნების endpoint არ აქვს; Publish Telegram-ში მფლობელის მოქმედებას საჭიროებს.

## შემდგომი საჭირო ნაბიჯები

- რეალური, დახურული პილოტი ახალი ბოტით, ცალკე სატესტო არხითა და API account-ით.
- წყაროები, განრიგი და FLASH/QUICK/STANDARD/DEEP მოცულობები მფლობელისგან.
- ცნობილი საერთო წყაროების/მედიასაკუთრებების რუკის შევსება.
- ადამიანური შეფასების ნაკრები ქართულ ატრიბუციაზე, ომებზე, არჩევნებზე და ურთიერთსაწინააღმდეგო მტკიცებებზე.
- PostgreSQL backup-ის ავტომატური პოლიტიკა და აღდგენის პრაქტიკული ტესტი.
